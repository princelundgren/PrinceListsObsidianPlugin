# Step 1a checks

Plan step 1a, Task 13, Steps 1 to 4. Every check in them passed.

- **On the Mac:** scripted through Obsidian's CLI (`obsidian eval`) in a test vault.
- **On the iPhone:** scripted through Safari's Web Inspector, which Obsidian documents for iOS 16.4
  and later, bridged with `ios_webkit_debug_proxy`. Touch events were synthetic.
- **By hand:** the maintainer checked the keyboard after "+", scrolling, and 2-second holds on a
  row and a heading, where lifting the finger opened nothing.
- **Versions:** Obsidian 1.14.4 on the Mac and 1.14.5 on the iPhone. The plugin was built from
  `main`.

## Step 1: the iPhone basics

1. Opening a list.
2. A tick, which writes `✔ <date> <time>`.
3. A title edit, which saves.
4. The card's ⋯ menu: New item below, New heading below, and Delete in red.
5. New item below, which adds the item.
6. A tap on a heading, whose menu has New item, New heading below, Rename heading, and Delete
   heading in red.
7. The pane's More options menu, whose "Show archived" shows the hidden done item.
8. Task 12's folder long-press: a long press on a folder in the file explorer reaches `file-menu`
   with source `file-explorer-context-menu` and offers "New list". Choosing it creates
   `<folder>/Untitled list.md`, opens it as a list and focuses the title.

## Step 2: alongside Tasks and Kanban

- **Setup:** Tasks and Kanban turned on for the session.
- **Opening:** lists open as lists from the file explorer, from a link, by quick-switcher-style
  link opening and in a new tab, and Back returns to the linking note.
- **Tasks query:** `not done` with `path includes <list>` lists the four open items with their ⏳
  and 📅 dates.

## Step 3: a Sync conflict

- **What was done:** Sync was paused on both devices, with Sync's own Pause, and the same item
  ticked on each, a minute apart.
- **After resuming:** both devices held `- [x] … ✔ <time A> ✔ <time B>`, and there was no
  conflict file. The view showed one done item.
- **The next edit:** an untick removed both marks, and a tick wrote one.

## Step 4: the fixtures in reading view

- **Item counts:** all ten fixtures, with the frontmatter removed, match the plugin's parser on
  both devices: `example` 5, `lazy` 2, `list-note-query` 1, `markers` 7, `notes-everything` 1,
  `pasted-items` 2, `title-heading` 2, `top-level-untouched` 2, `trailing-whitespace` 2,
  `unclosed` 1.
- **Notes:** they render inside their item.
- **`title-heading.md`:** item a's title renders as an h2 inside the item, which is CommonMark's
  setext rule. That's risk 4's "title becoming a heading".
- **The `✔` glyph:** on the Mac it reads as a text check mark in reading view, not as an emoji.

## Earlier checks

- **The flash:** none seen, on the Mac or the iPhone
  ([spike 1](2026-10-21-spike-open.md)).
- **Back history:** it holds, with one stop after an automatic switch to Markdown.
- **iPhone gestures:** a hold opens no menu and selects no text, and the tap that ends a hold is
  swallowed. Obsidian's own haptic on a hold stays: no documented API turns it off.
- **Notes outside the vault:** on the Mac, opening, rendering, writing, renaming and links work.
- **A 500-item list with 100 Markdown titles:** it opens in 138 ms on the iPhone and scrolls at
  8 ms a frame (120 Hz).
- **Obsidian Sync with near-simultaneous edits on two devices:** this can lose one side's change,
  as in Obsidian's own editor. When it takes typing, the plugin offers "Copy text".
